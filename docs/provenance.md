# Operational Provenance for Agent-Produced Artifacts

How securetty tracks the origin of agent-generated content across commits, PR/MR comments, and CI artifacts.

## What Provenance Means in securetty

When an AI agent produces output inside a securetty container -- a commit, a review comment, a CI artifact -- the provenance metadata records which agent produced it, which model backed it, and which session it belonged to. This satisfies two requirements:

1. **DCO compliance** -- AI-generated commits carry `Assisted-by` trailers instead of misleading `Co-Authored-By` or `Signed-off-by` lines (issues #44, #46).
2. **Artifact traceability** -- CI artifacts and PR/MR comments carry machine-readable metadata so reviewers and audit tooling can distinguish human from agent output (issue #99).

## The Provenance Script

`roles/containers/files/securetty-provenance.sh` generates provenance metadata in three formats depending on the output target.

### Environment Variables

| Variable | Purpose | Default |
|----------|---------|---------|
| `SECURETTY_AGENT` | Agent name (e.g., `claude`, `copilot`, `goose`) | `claude` |
| `CLAUDE_MODEL` | Model identifier (e.g., `claude-opus-4-20250514`) | `unknown` |
| `CLAUDE_SESSION_ID` | Session identifier for tracing | `unknown` |

All three can be overridden per-invocation with `--agent`, `--model`, and `--session` flags.

### Output Modes

#### `--commit` -- Git Trailer Format

Produces DCO-compliant git trailers suitable for appending to commit messages. This is the library equivalent of what `claude-post-commit-hook.sh` appends automatically.

```
$ securetty-provenance.sh --commit
Assisted-by: claude (claude-opus-4-20250514)
Agent-Model: claude-opus-4-20250514
Agent-Session: abc123
```

#### `--comment` -- Markdown Footer

Produces a markdown divider and italic attribution line for PR/MR comments. Append this to any agent-generated review comment or summary.

```
$ securetty-provenance.sh --comment
---
_Generated by securetty | agent: claude | model: claude-opus-4-20250514 | session: abc123_
```

#### `--artifact` -- JSON Metadata

Produces a single-line JSON object for embedding in or alongside CI artifacts (SARIF files, SBOM annotations, scan reports).

```
$ securetty-provenance.sh --artifact
{"generator":"securetty","agent":"claude","model":"claude-opus-4-20250514","session":"abc123","timestamp":"2025-07-15T14:30:00Z"}
```

## Usage in CI Pipelines

### GitHub Actions

```yaml
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Generate review comment
        env:
          CLAUDE_MODEL: ${{ vars.CLAUDE_MODEL }}
          CLAUDE_SESSION_ID: ${{ github.run_id }}
        run: |
          review_body=$(run-agent-review)
          footer=$(./roles/containers/files/securetty-provenance.sh --comment)
          printf '%s\n%s\n' "$review_body" "$footer" > comment.md

      - name: Attach artifact provenance
        env:
          CLAUDE_MODEL: ${{ vars.CLAUDE_MODEL }}
          CLAUDE_SESSION_ID: ${{ github.run_id }}
        run: |
          ./roles/containers/files/securetty-provenance.sh --artifact > provenance.json

      - uses: actions/upload-artifact@v4
        with:
          name: scan-results
          path: |
            results.sarif
            provenance.json
```

### GitLab CI

```yaml
agent-review:
  stage: review
  variables:
    CLAUDE_MODEL: "claude-opus-4-20250514"
    CLAUDE_SESSION_ID: "$CI_JOB_ID"
  script:
    - review_body=$(run-agent-review)
    - footer=$(./roles/containers/files/securetty-provenance.sh --comment)
    - printf '%s\n%s\n' "$review_body" "$footer" > comment.md
    - ./roles/containers/files/securetty-provenance.sh --artifact > provenance.json
  artifacts:
    paths:
      - provenance.json
    reports:
      dotenv: provenance.json
```

### CLI Overrides

For pipelines where env vars are not set or a different agent produced the output:

```bash
securetty-provenance.sh --artifact \
  --agent goose \
  --model gpt-4o \
  --session "run-${CI_JOB_ID}"
```

## Relationship to Existing Hooks

The post-commit hook (`claude-post-commit-hook.sh`) handles commit-time provenance automatically -- it strips misleading AI `Co-Authored-By` lines and appends `Assisted-by`, `Agent-Model`, and `Agent-Session` trailers. The provenance script does not replace that hook; it extends the same metadata to non-commit outputs (comments, artifacts) where git trailers do not apply.

## WG Compliance

This implementation follows the agent-action-provenance best practice: every agent-produced artifact carries metadata identifying the generating agent, model, session, and timestamp. The three output modes cover the standard artifact surfaces (VCS commits, code review comments, CI pipeline outputs) so provenance is available regardless of where agent output lands.
